# Appendix: GCENodeClass / GKE field-and-feature audit

Source assessment for [proposal 0012](../0012-beta-api-graduation.md), 2026-11-16; disposition inventories updated 2026-11-17. This is a completed **source-level audit**, not evidence of live-cloud support or an implementation commitment.

Repository Terraform examples pin **6.28.0**; this audit intentionally uses the newer stable comparator, not a proposed dependency upgrade. Beta-only documentation is not proof of availability in that GA schema.
- [GKE v1 discovery snapshot](https://github.com/googleapis/google-api-go-client/blob/1179cf891c4a7c26ef6facb6956e82bfeb2ec32f/container/v1/container-api.json), commit `1179cf89`, supplements Terraform. REST presence does not establish feature GA, standalone-VM support or entitlement.

**Status:** C = explicit capability; P = partial/different semantics; H = source-dependent, no NodeClass control; M = missing; O = owned elsewhere; X = intentionally outside scope. C does not mean defaults/limits equal GKE or that tests were run.

**Decisions:** Ignore = no delivery commitment in these milestones (already covered, approved exception, deferred feature or out of scope—not a claim of support). Fix before beta / Fix before stable = proposed delivery gates. Support status is separate; “not planned” means outside the accepted scope unless a new proposal changes it. Maintainer review must approve these dispositions.

| Terraform option(s)                                                                                                                                          | Current support / gap                                                                                                                                                                                   |
|--------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `hugepages_config.hugepage_size_2m`, `hugepage_size_1g`                                                                                                      | `linuxNodeConfig.hugepages.hugepageSize2m/1g`; GKE REST itself calls the parent `hugepages`. Runtime boot metadata exists, but scheduling needs NodeOverlay; no intrinsic hugepage capacity prediction. |
| `swap_config.enabled`, `encryption_config.disabled`, `boot_disk_profile.swap_size_gib`                                                                       | Explicit boot-disk swap, encrypted by default, with scheduler/storage accounting.                                                                                                                       |
| `swap_config.boot_disk_profile.swap_size_percent`, `dedicated_local_ssd_profile.disk_count`, `ephemeral_local_ssd_profile.{swap_size_gib,swap_size_percent}` | Missing profiles/percentage sizing. Existing nesting can accommodate additive extensions, with mutual-exclusion rules.                                                                                  |
| `sysctls`, `cgroup_mode`                                                                                                                                     | No explicit node-wide controls; source bootstrap may carry policy.                                                                                                                                      |
| `node_kernel_module_loading`, `accurate_time_config`, `custom_node_init`                                                                                     | No declared controls. Custom init cannot be simulated safely by unrestricted reserved metadata.                                                                                                         |
| `transparent_hugepage_enabled`, `transparent_hugepage_defrag`                                                                                                | No declared controls; static hugepages are a different feature.                                                                                                                                         |

The pinned GKE REST snapshot additionally declares kernel overrides, timezone, extra hosts/resolver entries, VFIO, disk-I/O scheduling, reserved-system-CPU/resource configuration and container-log worker/interval settings not exposed by the inspected Terraform blocks. M21 classifies these as **Ignore / not yet declaratively supported**, not demonstrated GA Terraform parity blockers. `effectiveCgroupMode` and pod range utilization are outputs, not requested spec fields.

## Networking and resource ownership

| Terraform pool/network field(s)                                                                                          | Current mapping / gap                                                                                                                                                                                                                                                                                                                                                                                                      |
|--------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `enable_private_nodes`, `subnetwork`                                                                                     | `networkConfig.enablePrivateNodes/subnetwork`; `setupNetworkInterfaces` reads `PrivateClusterConfig.EnablePrivateNodes` but not `NetworkConfig.DefaultEnablePrivateNodes`. A cluster with only the latter set does not inherit it through this code path; unlike fallback-pool construction, the renderer does not combine both. Fix/test the supported contract; this is source evidence, not a reproduced live incident. |
| `pod_range`                                                                                                              | `subnetRangeNames` (or deprecated singular): chooses among existing secondary ranges; not subnet selection.                                                                                                                                                                                                                                                                                                                |
| `additional_node_network_configs.{network,subnetwork}`                                                                   | `additionalNetworkInterfaces`; no per-extra-NIC stack selector. Primary NIC dual stack is derived from cluster/subnet configuration.                                                                                                                                                                                                                                                                                       |
| `additional_pod_network_configs`                                                                                         | No extra pod-network alias-IP/IPAM configuration. Additional VM NICs alone do not provide it.                                                                                                                                                                                                                                                                                                                              |
| `network_performance_config`                                                                                             | No bandwidth-tier setting in rendered Compute instance.                                                                                                                                                                                                                                                                                                                                                                    |
| `accelerator_network_profile`                                                                                            | No GKE-managed accelerated-network allocation integration.                                                                                                                                                                                                                                                                                                                                                                 |
| `pod_cidr_overprovision_config`                                                                                          | No disable toggle; `podCIDRRange` uses fixed maxPods-to-prefix logic.                                                                                                                                                                                                                                                                                                                                                      |
| `create_pod_range`, `pod_ipv4_cidr_block`                                                                                | Provider consumes existing ranges rather than creating GCP network infrastructure.                                                                                                                                                                                                                                                                                                                                         |
| `max_pods_per_node`                                                                                                      | `kubeletConfiguration.maxPods`; also drives IP allocation. Its schema accepts zero; omission/zero and pod-capacity/IPAM agreement need explicit acceptance tests.                                                                                                                                                                                                                                                          |
| `node_locations`                                                                                                         | NodePool topology requirements plus cluster zone discovery, not a NodeClass list.                                                                                                                                                                                                                                                                                                                                          |
| `autoscaling`, `node_count`, `initial_node_count`, `management`, `upgrade_settings`, pool `version`, `node_drain_config` | Karpenter NodePool/lifecycle or cluster/source-pool management; not missing per-VM configuration. Core expiration/disruption are not literal GKE policy equivalents.                                                                                                                                                                                                                                                       |
| `placement_policy`, `queued_provisioning`, `best_effort_provisioning`                                                    | No managed-pool/ProvisioningRequest orchestration or compact/TPU placement contract.                                                                                                                                                                                                                                                                                                                                       |

GKE REST `networkTierConfig` is **output-only**, inherited from cluster settings; do not call it a missing writable Terraform NodeClass field. A separate direct-GCE network-service-tier feature (#574) is still a valid additive request. Additional-network stack-type documentation marked beta is not treated as part of the pinned GA schema without schema verification.
