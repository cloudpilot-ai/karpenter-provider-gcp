# Appendix: source-template inheritance and behavior transitions

Current-code inventory for [proposal 0012](../0012-beta-api-graduation.md), baseline `401e78cf`. **No live template values or credentials were inspected.** Decisions below are proposed prerequisites, not implemented fixes.

## What can cross the source boundary

[GetSourceTemplateMetadata](../../pkg/providers/nodepooltemplate/sourcetemplate.go) returns **metadata only**, not wholesale instance-template properties. VM disks, NICs, service accounts, tags and hardware settings are rebuilt by the provider. [FromSourceTemplate](../../pkg/metadata/compute_metadata.go) imports the metadata/configuration channels; [instance orchestration](../../pkg/providers/instance/instance.go) separately adds selected readiness labels:

| Channel                                    | Proven current behavior                                                                                                                                                                                                                                                      | Decision / closure requirement                                                                                                                                                                              |
|--------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 22 raw metadata keys                       | Explicit outer-key allowlist; payloads can contain executable bootstrap/configuration and credentials. Valid custom metadata overrides permitted keys; generated kube-env/labels/config render afterward.                                                                    | **Fix before beta:** classify bootstrap-only versus configuration payloads; validate provenance and precedence. Do not remove a required installer merely to discard one feature's settings.                |
| `kube-env`                                 | All parsed entries survive except keys explicitly rewritten/deleted; unknown keys and multiline values remain.                                                                                                                                                               | **Fix before beta:** define the admitted bootstrap/configuration contract and unknown-key handling. An outer allowlist does not bound these nested options.                                                 |
| `kubelet-config`                           | Decode into the vendored kubelet type (126 directly declared named settings plus embedded TypeMeta `kind`/`apiVersion`); remove three shutdown fields and GracefulNodeShutdown gate first, then apply selective overlays. Unknown JSON fields are not a generic passthrough. | **Fix before beta:** account for every recognized field by inherited/overlaid/normalized/discarded rule; reconcile CLI precedence and resource accounting. Serialization is not byte-for-byte preservation. |
| `KUBELET_ARGS`                             | Keep unowned whitespace tokens; strip owned equals-form labels/taints/maxPods and GracefulNodeShutdown gate, then rebuild owned flags. This is not a shell parser; split-form flags need tests.                                                                              | **Fix before beta:** bound accepted flags, remove conflicting authority and test omission/empty/override behavior. Unknown preserved flags can defeat config-file overrides.                                |
| Source `kube-labels` / registration labels | Rebuilt, retaining only the six readiness keys below when target labels do not already supply them.                                                                                                                                                                          | **Ignore:** retain this explicit bootstrap contract; regression-test isolation from unrelated source labels.                                                                                                |
| Other outer metadata / template properties | Not copied by this metadata path.                                                                                                                                                                                                                                            | **Ignore:** not an implicit configuration source; do not infer feature support from a source pool's VM properties.                                                                                          |

This is an exhaustive inventory of the **current copy paths**, not a claim to enumerate every feature hidden in arbitrary GKE script/kube-env payloads. Those open-ended channels are themselves identified stabilization work: no “all inherited settings accounted for” sign-off until their supported boundary is explicit. Source-pool upgrades, selection changes and credential rotation can alter payloads without a NodeClass edit.

### Exact normalization boundaries

From [bootstrap overlays](../../pkg/providers/instance/metadata_bootstrap.go), [swap handling](../../pkg/providers/instance/metadata_swap.go), [binary patching](../../pkg/providers/instance/metadata_server_binary.go) and [instance orchestration](../../pkg/providers/instance/instance.go):

- Required kube-env inputs: `CA_CERT`, `KUBE_MANIFESTS_TAR_URL`, `KUBERNETES_MASTER_NAME`, `SERVER_BINARY_TAR_HASH`, `SERVER_BINARY_TAR_URL`. Presence validation is not proof that every payload is safe/current.
- Rewritten conditionally: `ZONE`, server URL/hash, COS I/O knobs, `SECONDARY_BOOT_DISKS`, `HUGEPAGE_2M/1G`, `ENABLE_CONTAINERD_HUGETLB_CONTROLLER`, GCFS cache size, and feature labels. Conditional branches do not necessarily erase all legacy encodings.
- Cleared swap keys: `NODE_SWAP_SIZE`, `NODE_SWAP_PROFILE`, `NODE_SWAP_ENCRYPTION`, `NODE_SWAP_DEDICATED_LOCAL_SSD_COUNT`, `NODE_ZSWAP_ENABLED`, `NODE_ZSWAP_COMPRESSOR`, `NODE_ZSWAP_MAX_POOL_PERCENT`.
- Sharing keys set/cleared: `GPU_SHARING_STRATEGY`, `MAX_SHARED_CLIENTS_PER_GPU`, `MAX_TIME_SHARED_CLIENTS_PER_GPU`. SSD targets use `NODE_LOCAL_NVME_SSD_BLOCK_EXT` / `NODE_EPHEMERAL_STORAGE_LOCAL_SSD`; zero-count behavior needs the ledger's regression.
- Kubelet source exclusions: `shutdownGracePeriod`, `shutdownGracePeriodCriticalPods`, `shutdownGracePeriodByPodPriority`; remove `featureGates.GracefulNodeShutdown`. The remaining **recognized** roots inherit unless the following layers override them.
- Eighteen explicit NodeClass kubelet fields: `clusterDNS`, `maxPods`, `podsPerCore`, `systemReserved`, `kubeReserved`, `evictionHard`, `evictionSoft`, `evictionSoftGracePeriod`, `evictionMaxPodGracePeriod`, `imageGCHighThresholdPercent`, `imageGCLowThresholdPercent`, `cpuCFSQuota`, `serializeImagePulls`, `maxParallelImagePulls`, `failSwapOn`, `memorySwap`, `shutdownGracePeriod`, `shutdownGracePeriodCriticalPods`. Map overlays merge; scalar pointers override when present. Swap defaults/reservations are applied afterward.

These rules account for the 126 directly declared settings of the [vendored kubelet type](../../vendor/k8s.io/kubelet/config/v1beta1/types.go) by membership: excluded, explicitly overlaid/normalized, or remaining inherited typed values. Embedded `kind`/`apiVersion` are also preserved; before beta, define validation/normalization against supported kubelet config versions rather than assuming unknown versions are compatible. They do not claim that every inherited setting is safe or modeled by scheduler capacity. The accepted beta contract must close that gap, not merely count fields.

## #788: why a new optional field can still break behavior

[GKE documents per-option precedence](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/customize-containerd-configuration): node-pool options override cluster options; unrelated defaults remain inherited. `registryHosts: []` explicitly disables registry-host configuration; omission is different.

The [issue's proposed contract](https://github.com/karpenter-gcp/karpenter-provider-gcp/issues/788) intentionally changes the authority from a selected source pool to cluster defaults plus NodeClass overrides. If the source pool has different settings, existing NodeClasses with the new field **omitted** can launch differently after upgrade. Treat that as a semantic migration, not automatically as an additive API change.

Each transition needs: current source/encoding; desired authority and feature-specific merge rule; omitted/false/zero/empty behavior; old/new effective-config diff; secret-safe provenance; replacement/drift behavior; migration/rollback; owner, issue and milestone. Use synthetic/sanitized fixtures where cluster defaults and source-pool values deliberately disagree. Do not archive credential-bearing templates as documentation.

Cluster-default resolution/policy belongs in provider orchestration and shared GKE facts; `pkg/metadata` stays a pure parse/mutate/render boundary. Removing source configuration must not remove bootstrap inputs required to reconstruct the target.

## Exit criteria

**Before beta:** approve the complete copy-path inventory and feature-authority ledger; deliver beta-marked outcomes (bounded inheritance only where that row explicitly permits it), and test omitted/disabled states and source changes. Unclassified wildcard configuration cannot be signed off as stable behavior.

**Before stable:** complete the accepted explicit-control work, remove unapproved source-pool feature inheritance, and prove beta→v1 migrations/effective-config continuity. Approved bootstrap dependencies may remain; opaque copying is not a reason to promise unsupported features.
