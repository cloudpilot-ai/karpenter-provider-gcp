# Reporting Security Issues

If you discover a potential security issue in this project, email [CloudPilot AI Security](mailto:security@cloudpilot.ai). This is the existing project reporting address. Please do not create a public GitHub issue or include credentials, kubeconfigs, service-account keys, or unrelated personal data.

Include affected versions, impact, and reproduction steps or a minimal proof of concept, with sensitive infrastructure identifiers redacted.

## Proposed response ownership and handling

**Pending maintainer approval and access confirmation:** the [maintainers](MAINTAINERS.md) would collectively serve as the security response team under [governance](GOVERNANCE.md). This draft does not assert that every maintainer can access the CloudPilot AI mailbox or has accepted response duties. Before adoption, confirm willing named responders, secure access, and a private escalation route if the mailbox is unavailable or a responder is implicated.

The proposed team's responsibilities are to:

1. Acknowledge and privately triage reports, assess affected versions and impact, and coordinate with the reporter.
2. Limit report access to responders who need it; exclude implicated responders and arrange an independent handler where necessary.
3. Coordinate remediation, tests, and release preparation privately, involving affected upstream projects when appropriate.
4. Agree a disclosure plan with the reporter and affected parties, publish fixes and an advisory with affected/fixed versions and mitigations, and credit the reporter with their consent.
5. Review response ownership and access at least annually and on role changes.

No response-time, fix-time, support-window, or embargo guarantee is introduced. A private mailbox alone does not demonstrate that this response process is operational. Until response ownership and escalation are confirmed, those remain [unresolved policy decisions](docs/community/cncf-policy-alignment.md). Do not use public issue escalation for an undisclosed vulnerability.
