# CNCF Incubation readiness

This is a working evidence checklist for a **direct Incubation application**, not an application, completed self-assessment, CNCF membership claim, or assertion of compliance. New governance and response procedures in this PR are proposals for maintainer review, not established practice. A file's existence is not evidence that its policy has been adopted or exercised.

## Assessment basis

The assessment uses CNCF TOC revision [`8d256dfc246e13b37cff3f91c2d6a02702706804`](https://github.com/cncf/toc/tree/8d256dfc246e13b37cff3f91c2d6a02702706804):

Direct Incubation is explicitly allowed by the triage guide. At this revision, items including the maintainer lifecycle and contributor ladder are required by the application but marked suggested in the governance-review template. This checklist follows the **application's required criteria**, while retaining both sources for review. Recheck current CNCF requirements before submission.

The roster layout is adapted from the [CNCF project template](https://github.com/cncf/project-template/blob/e66ba44f724d00f66c84932593c5a229fee3564b/MAINTAINERS.md). The proposed voting thresholds and lifecycle mechanics are local design choices, not mandatory CNCF formats. This PR does not introduce a CLA, DCO requirement, license change, new legal agreement, or a duplicate machine-readable roster.

## External submissions and onboarding

Local files do not replace required external artifacts. The pinned TOC triage guide calls for a GTR snapshot in `cncf/toc/projects/<project-name>/tech-review/YYYY-MM-DD.md`, and references a completed security self-assessment at `cncf/toc/projects/<project>/security-assessment/self-assessment.md`. Prepare self-assessed technical and governance working copies, then coordinate vetted snapshots with CNCF reviewers according to the current process. Track the external snapshots separately from local working documents.

Before submission, maintainers must also confirm the project name/trademark, license/dependency compliance, account and asset control, and rights-holder readiness for CNCF agreements or transfers. The Apache-2.0 [license](../../LICENSE.txt) is existing evidence, not a completed legal review. Resolve any vendor-neutrality or branding changes through explicit review rather than silently removing sponsorship acknowledgements or claiming assets have already transferred.

This PR does not submit an application, publish to `cncf/toc`, register a badge, contact adopters or reviewers, change GitHub settings, sign agreements, transfer assets, or modify infrastructure. Each requires separate authorization. Keep the PR draft while governance adoption and the explicitly unresolved response-policy items remain under review.
